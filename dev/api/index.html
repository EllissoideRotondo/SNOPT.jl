API reference

Solve a problem

SNOPT.snopt — Function
snopt(eval_obj, eval_grad, x0; lb = nothing, ub = nothing,
      eval_con = nothing, eval_jac = nothing, lcon = nothing, ucon = nothing,
      J = nothing, options = nothing, callback = nothing, snlog = nothing,
      snstop = nothing, printfile = "", summfile = "", start = "Cold",
      basis = nothing, name = "Julia") -> SnoptResult

Minimize eval_obj(x) subject to variable bounds and optional nonlinear constraints, and return a SnoptResult.

snopt creates a SNOPT workspace of the necessary size, solves the problem with SNOPT's snOptB interface, and closes the workspace. It does not change x0 or the bound arrays. See Getting started for a tutorial.

Arguments

  • eval_obj(x): return the objective value as a real number.
  • eval_grad(g, x): write the objective gradient into g. Write every entry.
  • x0: starting point, nonempty and finite. Its length n is the number of variables.

Keywords

  • lb, ub: variable bounds. A scalar applies to every variable; a vector has length n. nothing and ±Inf mean no bound.
  • eval_con(c, x): write the m constraint values into c.
  • eval_jac(vals, x): write the Jacobian entries into vals, in the order of J.nzval (column by column).
  • lcon, ucon: constraint bounds, vectors of length m. Equal values give an equality constraint. Give eval_con, eval_jac, lcon and ucon together.
  • J: sparsity pattern of the m × n Jacobian as a SparseMatrixCSC. The stored values are ignored. nothing means that every entry can be nonzero.
  • options: SNOPT options as a vector of name => value pairs; see Set solver options.
  • callback(event): called after each evaluation of the objective or the constraints, with a NamedTuple.
  • snlog(event): called once per major iteration with a SnoptMajorLog.
  • snstop(event): called once per major iteration with a SnoptStopEvent.
  • start: "Cold", or "Warm" to start from basis.
  • basis: SnoptBasis of an earlier result with the same n and m.
  • printfile, summfile: paths of the SNOPT log and summary. "" writes no file.
  • name: problem name in the SNOPT log, at most 8 bytes.

If callback, snlog or snstop returns false, SNOPT stops and the result has a status from SnoptStatus.StopInFunction to SnoptStatus.StopInMonitor (codes 71–74). See Monitor and stop a solve.

Throws an ArgumentError for input that is not valid, for example a NaN bound, a lower bound above its upper bound, an array of the wrong length, an unknown option, a name longer than 8 bytes or start = "Hot". An error thrown by a user function is thrown again after the workspace is closed.

Only one solve runs at a time in a Julia process; a second call waits until the first returns. See Solver concepts.

Examples

objective(x) = (x[1] - 1.0)^2 + (x[2] - 2.0)^2
function gradient!(g, x)
    g[1] = 2.0 * (x[1] - 1.0)
    g[2] = 2.0 * (x[2] - 2.0)
    return nothing
end

result = snopt(objective, gradient!, [0.0, 0.0]; lb = -10.0, ub = 10.0)
result.x   # ≈ [1.0, 2.0]

SNOPT.SnoptResult — Type
SnoptResult

Result of snopt.

Check status before using x, for example result.status == SnoptStatus.Optimal.

Fields

  • status: outcome of the solve, a SnoptStatus value; Int(status) is the SNOPT status code.
  • objective: objective value at x.
  • x: solution, length n.
  • lambda: Lagrange multipliers, one per variable and then one per constraint.
  • num_inf: number of bounds and constraints that are still violated.
  • sum_inf: sum of these violations.
  • iterations: total number of minor iterations.
  • major_itns: number of major iterations.
  • run_time: CPU time of the solve reported by SNOPT, in seconds.
  • memory: SnoptMemory used to size the workspace.
  • basis: SnoptBasis for a warm start.

If a callback function stopped the solve before SNOPT started, basis contains no information and the iteration counts are zero.

SNOPT.SnoptBasis — Type
SnoptBasis

Basis at the end of a solve, for a warm start with snopt.

Pass result.basis as the basis keyword of a later call, together with start = "Warm". See Warm and hot starts and Solver concepts.

Fields

  • hs: basis state of each variable and slack variable (Int32), length n + m.
  • nS: number of superbasic variables.
  • n: number of variables.
  • m: number of constraint rows; 1 for a problem without constraints.

SNOPT.SnoptStatus — Module
SnoptStatus

Status of a SNOPT solve. Each value of type SnoptStatus.T is a SNOPT 7.7 status code: SnoptStatus.T(51) gives SnoptStatus.IncorrectObjectiveDerivatives, and Int gives the code back. The tens digit is the group, so Int(status) ÷ 10 == 1 holds for every infeasible outcome. SnoptStatus.Unknown (0) stands for a code that the SNOPT 7.7 user guide does not list. Solver concepts describes each group.

Examples

julia> SnoptStatus.T(51)
SnoptStatus.IncorrectObjectiveDerivatives = 51

julia> Int(SnoptStatus.TimeLimit)
34
source
SNOPT.status_from_code — Function
SNOPT.status_from_code(code::Integer) -> SnoptStatus.T

Return the SnoptStatus value of the SNOPT status code code, or SnoptStatus.Unknown for a code that the SNOPT 7.7 user guide does not list. Unlike SnoptStatus.T(code), it never throws, so it is safe to call on the code returned by snopt!, snopta!, snoptb! or snoptc!.

Monitor a solve

SNOPT.SnoptMajorLog — Type
SnoptMajorLog

State of the solve at the end of one major iteration, passed to the snlog function.

Return false from snlog to stop the solve; return any other value to continue. See Monitor and stop a solve. SNOPT computes most values on its scaled problem. The arrays are copies and stay valid after snlog returns.

Fields

  • iteration: total number of minor iterations so far.
  • major_iter: number of the current major iteration.
  • minor_iter: number of minor iterations in the current major iteration.
  • n_superbasics: number of superbasic variables.
  • n_swaps: number of basis changes.
  • objective: objective value, including objective_add and a linear objective row.
  • merit: value of the merit function, the objective plus a penalty on the constraint violation.
  • f_objective, f_merit: nonlinear part of the objective and of the merit function.
  • primal_infeasibility: constraint violation (scaled).
  • dual_infeasibility: error in the optimality conditions (scaled).
  • max_violation, relative_violation: largest constraint violation, absolute and relative.
  • step: length of the last step.
  • penalty_norm: norm of the penalty parameters of the merit function.
  • condition_hessian: estimated condition number of the reduced Hessian.
  • objective_scale, objective_add: scale factor and constant of the objective.
  • minimize: 1 to minimize, -1 to maximize.
  • kt_conditions: two flags, true when the primal and the dual parts of the Karush–Kuhn–Tucker (KKT) optimality conditions are satisfied.
  • n: number of variables.
  • nb: number of variables plus number of slack variables.
  • nncon: number of nonlinear constraints.
  • nnobj: number of nonlinear objective variables.
  • x: variables followed by slack variables, length nb.
  • fcon, fx: nonlinear constraint values as SNOPT passes them (fCon and Fx), length nncon.
  • ycon: multipliers of the nonlinear constraints, length nncon.
  • hs: basis states, length nb.
source
SNOPT.SnoptStopEvent — Type
SnoptStopEvent

State of the solve at the end of one major iteration, passed to the snstop function.

This type has all the fields of SnoptMajorLog and the fields below. Return false from snstop to stop the solve; the result then has the status SnoptStatus.StopInMonitor. See Monitor and stop a solve.

Fields

  • m: number of constraint rows.
  • max_superbasics: largest allowed number of superbasic variables.
  • negcon: number of nonlinear Jacobian entries.
  • gobj: objective gradient, length nnobj.
  • gcon: nonlinear Jacobian entries, length negcon.
  • pi: multipliers of the rows, length m.
  • rc: reduced costs of the variables and slack variables, length nb.
  • rg: reduced gradient, length max_superbasics.
  • bl, bu: scaled lower and upper bounds, length nb.
source
SNOPT.snopt_no_progress — Function
snopt_no_progress(event) -> true

Return true for every event, so the solve never stops.

Pass it as callback, snlog or snstop where a function that never stops the solve is needed. The default value nothing of these keywords has the same effect and is faster, because SNOPT.jl then does not create the event.

Workspace and options

SNOPT.initialize — Function
initialize(printfile, summfile, leniw = 30500, lenrw = 60000) -> SnoptWorkspace
initialize(f, printfile, summfile, leniw = 30500, lenrw = 60000)

Open a SNOPT workspace with work arrays of length leniw (integer) and lenrw (real), and return it.

printfile and summfile are the paths of the SNOPT log and summary; "" writes no file. Both lengths must be at least 500. Use snmemb to find the sizes for a large problem.

The second form calls f(workspace) and returns its value. It closes the workspace when f returns and also when f throws an error, which it then throws again. After the first form, close the workspace with close.

Only one workspace can be open in a Julia process, so initialize closes the previous workspace. Do not call initialize from a callback function during a solve. Throws an error if the SNOPT library is not loaded.

Examples

initialize("", "") do workspace
    set_option!(workspace, "Major print level", 0)
    # Build and solve a low-level problem.
end
source
SNOPT.SnoptWorkspace — Type
SnoptWorkspace

SNOPT session with its integer and real work arrays.

Create a workspace with initialize, and close it with close or with the do form of initialize. isopen(workspace) tells if it is still open. Only one workspace can be open in a Julia process: initialize closes the previous one. snopt manages its own workspace, so this type is needed only for the Low-level interface.

The only public field is iw, the integer work array, which the callback builders make_objfun, make_confun and make_usrfun_c take as an argument.

source
SNOPT.set_option! — Function
set_option!(ws, option::String) -> Int
set_option!(ws, name::String, value::Real) -> Int

Set one SNOPT option in the workspace ws and return 0.

ws is an open SNOPT.SnoptWorkspace or a low-level problem. The first form takes the full option text, for example "Hessian limited memory". The second form takes the option name and a number, for example set_option!(ws, "Major iterations limit", 500).

Throws an ArgumentError if SNOPT does not accept the option, if value is a Bool or not finite, or if the workspace is closed. To set options in snopt, use its options keyword instead; see Set solver options.

source
SNOPT.read_options — Function
read_options(ws, specsfile::String) -> Int

Read SNOPT options from the specs file specsfile into the workspace ws, and return the SNOPT status code.

ws is an open SNOPT.SnoptWorkspace or a low-level problem. The status code is 101 if SNOPT read the file without errors; otherwise SNOPT.jl shows a warning, and specs_status_message explains the code. Throws an ArgumentError if the file does not exist. See Set solver options for the file format.

source
SNOPT.specs_status_message — Function
specs_status_message(info::Int) -> String

Return a description of the status code info from read_options.

101 means that SNOPT read the specs file without errors. A code info > 134 means that SNOPT found info - 134 errors in the file.

source
SNOPT.snmemb — Function
snmemb(m, n, neJ, negCon, nnCon, nnObj, nnJac; options = nothing,
       printfile = "", summfile = "") -> SnoptMemory

Return the minimum workspace sizes that SNOPT needs for an snOptB or snOptC problem.

The arguments are the problem dimensions: m constraint rows (at least 1), n variables, neJ Jacobian entries, negCon nonlinear Jacobian entries, nnCon nonlinear constraints, nnObj nonlinear objective variables and nnJac nonlinear Jacobian variables. Some options change the sizes, so pass the options that the solve will use.

snmemb opens and closes a temporary workspace, so it closes any open workspace. Throws an ArgumentError if the dimensions are not consistent.

Examples

memory = snmemb(m, n, neJ, negCon, nnCon, nnObj, nnJac)
initialize("", "", memory.miniw, memory.minrw) do workspace
    # Build and solve the problem.
end
source
SNOPT.SnoptMemory — Type
SnoptMemory

Minimum workspace sizes returned by snmemb.

Fields

  • info: SNOPT status code of the estimate. 100 and 104 mean success.
  • miniw: minimum length of the integer work array.
  • minrw: minimum length of the real work array.

Low-level problem types

SNOPT.AbstractSnoptProblem — Type
AbstractSnoptProblem

Supertype of the low-level problem types SnoptA, SnoptB and SnoptC.

Each problem holds a SNOPT.SnoptWorkspace, the problem data and the user functions. snopt! solves any subtype in place.

source
SNOPT.SnoptA — Type
SnoptA(ws, nf, n, objadd, objrow, iAfun, jAvar, A, iGfun, jGvar,
       xlow, xupp, flow, fupp, x, xstate, xmul, F, Fstate, Fmul,
       status, nS, num_inf, sum_inf, usrfun)

Low-level problem for SNOPT's snOptA interface. Solve it with snopta!.

All objective and constraint functions form one vector F(x) of nf rows, and row objrow is the objective. The derivatives of F have a constant (linear) part and a part that usrfun computes. If usrfun gives no derivatives, set the option "Derivative option" to 0, and SNOPT estimates them by finite differences. Build usrfun with make_usrfun_a. The arguments are the fields, in this order. See Low-level interface for an example.

Fields

  • ws: open SNOPT.SnoptWorkspace.
  • nf, n: number of rows of F and number of variables.
  • objadd: constant added to the objective.
  • objrow: index of the objective row in F; 0 for no objective.
  • iAfun, jAvar, A: row indices, column indices and values of the constant derivative entries. Equal lengths; indices are Int32.
  • iGfun, jGvar: row and column indices (Int32) of the derivative entries that usrfun computes. Equal lengths.
  • xlow, xupp: variable bounds, length n. Use ±1.0e20 for no bound.
  • flow, fupp: row bounds, length nf. Use ±1.0e20 for no bound.
  • x, xstate, xmul: variables, their basis states (Int32) and multipliers, length n. x is the starting point on input and the solution on output.
  • F, Fstate, Fmul: row values, their basis states (Int32) and multipliers, length nf.
  • status, nS, num_inf, sum_inf: outputs. Pass 0, 0, 0, 0.0. After a solve they hold the status code, the number of superbasic variables, and the number and sum of infeasibilities.
  • usrfun: function from make_usrfun_a.

snopta! throws a DimensionMismatch if the array lengths do not agree.

source
SNOPT.SnoptB — Type
SnoptB(ws, n, nc, m_eff, nnobj, x, bl, bu, hs, J, obj_val, status, lambda,
       objfun, confun, nS = 0)

Low-level problem for SNOPT's snOptB interface, with separate objective and constraint functions. Solve it with snoptb!.

snopt builds this type internally. The arrays x, bl, bu and hs have length n + m_eff: the variables first, then one slack variable per constraint row. Build objfun with make_objfun and confun with make_confun or make_dummy_confun. The arguments are the fields, in this order. See Low-level interface for an example.

Fields

  • ws: open SNOPT.SnoptWorkspace.
  • n: number of variables.
  • nc: number of constraints. All are nonlinear, and nonlinear in all n variables.
  • m_eff: number of constraint rows, max(nc, 1). SNOPT needs at least one row, so a problem without constraints has one row with infinite bounds.
  • nnobj: the objective is nonlinear in x[1:nnobj] only; usually n.
  • x: starting point on input, solution on output. Length n + m_eff.
  • bl, bu: bounds of the variables and the rows. Length n + m_eff. Use ±1.0e20 for no bound.
  • hs: basis states (Int32), length n + m_eff. Zeros for a cold start.
  • J: m_eff × n Jacobian sparsity pattern as SparseMatrixCSC{Float64, Int32} with at least one entry.
  • obj_val, status, lambda: outputs. Pass 0.0, 0, Float64[]. After a solve they hold the objective value, the status code and the multipliers.
  • objfun, confun: functions from the callback builders.
  • nS: number of superbasic variables. 0 for a cold start; after a solve, the value for a warm start.
source

SNOPT.SnoptC — Type
SnoptC(ws, n, nc, m_eff, nnobj, x, bl, bu, hs, J, obj_val, status, lambda,

SNOPT.snopt! — Function
snopt!(prob::AbstractSnoptProblem; start = "Cold", name = "Julia",
       snlog = nothing, snstop = nothing) -> Int

Solve a low-level problem in place and return the SNOPT status code.

Calls snopta!, snoptb! or snoptc! for the type of prob; see these functions for the results that they write into prob.

start is "Cold", "Warm" or "Hot". A warm start uses the basis states and nS stored in prob. A hot start also reuses the basis factorization and the Hessian approximation of the previous solve, so it is valid only with the same prob and the same open workspace. snlog and snstop work as in snopt. name is the problem name in the SNOPT log, at most 8 bytes.

Throws an ArgumentError if the workspace is closed, if a solve is already running, if start is not one of the three modes, or if name is longer than 8 bytes. An error thrown by a user function is thrown again after the solve; the workspace stays open.

source
SNOPT.snopta! — Function
snopta!(prob::SnoptA; start = "Cold", name = "Julia", snlog = nothing,
        snstop = nothing) -> Int

Solve prob in place with SNOPT's snOptA interface and return the SNOPT status code.

After the solve, prob.x, prob.F, prob.xmul, prob.Fmul, prob.xstate, prob.Fstate and prob.status hold the result. The keywords are the same as for snopt!. If prob.usrfun gives no derivatives, set the option "Derivative option" to 0 before the solve.

Throws a DimensionMismatch if the array lengths in prob do not agree.

Callback builders

SNOPT.make_usrfun_a — Function
make_usrfun_a(eval_F; eval_G = nothing, callback = nothing)

Wrap eval_F(F, x) and eval_G(G, x) in the user function of a SnoptA problem.

eval_F(F, x) writes every row value into F. eval_G(G, x) writes the derivative at position (iGfun[k], jGvar[k]) into G[k]. If eval_G is nothing, SNOPT estimates the derivatives by finite differences; then set the option "Derivative option" to 0.

If callback is a function, it is called after each evaluation of F with a NamedTuple with the fields kind = :function, x and F. If it returns false, SNOPT stops.

source
SNOPT.make_objfun — Function
make_objfun(eval_obj, eval_grad, ws_iw; callback = nothing)

Wrap eval_obj(x) and eval_grad(g, x) in the objective function of a SnoptB problem.

eval_obj(x) returns the objective value; eval_grad(g, x) writes every entry of the gradient into g. Pass the integer work array workspace.iw as ws_iw.

If callback is a function, it is called after each objective evaluation with a NamedTuple with the fields kind = :objective, mode, major_iter, minor_iter, x and f. If it returns false, SNOPT stops. During a solve, major_iter and minor_iter are 0; use snlog for iteration counts.

source
SNOPT.make_confun — Function
make_confun(eval_con, eval_jac, J, ws_iw; callback = nothing)
make_confun(eval_con, eval_jac, J)

Wrap eval_con(c, x) and eval_jac(vals, x) in the constraint function of a SnoptB problem.

eval_con(c, x) writes every constraint value into c. eval_jac(vals, x) writes the Jacobian entries into vals, in the order of J.nzval. Pass the integer work array workspace.iw as ws_iw.

If callback is a function, it is called after each constraint evaluation with a NamedTuple with the fields kind = :constraint, mode, major_iter, minor_iter, x and c. If it returns false, SNOPT stops. During a solve, major_iter and minor_iter are 0; use snlog for iteration counts.

source
SNOPT.make_dummy_confun — Function
make_dummy_confun()

Return a constraint function that does nothing, for a SnoptB problem without constraints.

SNOPT needs a constraint function even when there are no nonlinear constraints.

source
SNOPT.make_usrfun_c — Function
make_usrfun_c(eval_obj, eval_grad, eval_con, eval_jac, J, ws_iw; callback = nothing)
make_usrfun_c(eval_obj, eval_grad, eval_con, eval_jac, J)

Wrap the objective and constraint functions in the user function of a SnoptC problem.

The four functions have the same form as in snopt: eval_obj(x) returns the objective, eval_grad(g, x) writes the gradient, eval_con(c, x) writes the constraint values, and eval_jac(vals, x) writes the Jacobian entries in the order of J.nzval. Pass workspace.iw as ws_iw.

If callback is a function, it is called after each evaluation with a NamedTuple with the fields kind = :combined, mode, major_iter, minor_iter, x, f and c. If it returns false, SNOPT stops. During a solve, major_iter and minor_iter are 0; use snlog for iteration counts.

SNOPT.make_snlog — Function
make_snlog(callback)

Wrap callback in a function that SNOPT can call once per major iteration.

SNOPT.jl calls callback with a SnoptMajorLog. If it returns false, SNOPT stops. The solve functions call make_snlog when they receive the snlog keyword, so a direct call is rarely necessary.

make_snstop(callback)

Wrap callback in a function that SNOPT can call once per major iteration.

SNOPT.jl calls callback with a SnoptStopEvent. If it returns false, SNOPT stops with status code 74 (SnoptStatus.StopInMonitor). The solve functions call make_snstop when they receive the snstop keyword, so a direct call is rarely necessary.

Library setup

These functions are not exported. Call them as SNOPT.has_snopt() and SNOPT.find_snopt_lib().

SNOPT.has_snopt — Function
has_snopt() -> Bool

Return true if SNOPT.jl found a usable SNOPT library when the package was loaded.

If this is false, each solve throws an error. Use SNOPT.find_snopt_lib to find the cause, and see Troubleshooting.

source
SNOPT.find_snopt_lib — Function
find_snopt_lib() -> String

Search for a usable libsnopt7 and return its absolute path, or "" if none is found.

A library is usable if it loads and contains every C function that SNOPT.jl calls. The search checks, in order: the directory in SNOPTDIR; the directories in LD_LIBRARY_PATH, DYLD_LIBRARY_PATH (macOS) or PATH (Windows); and the default locations of the system loader. If SNOPTDIR is set but contains no usable library, a warning is shown.

SNOPT.jl runs this search once when the package loads and stores the result in SNOPT.libsnopt7. A later call does not change SNOPT.libsnopt7; use it to diagnose a library setup problem, and restart Julia after the correction. See also SNOPT.has_snopt.
